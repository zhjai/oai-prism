# 客户端工具调用

Prism 在远端沙箱执行自己的工具，不能直接执行 API 调用方提供的自定义函数。网关通过提示词让模型描述调用，校验后返回 Chat Completions、Responses 或 Anthropic 的工具调用结构，由客户端执行，再把结果发回来。这是客户端协议桥接，不是 Prism 上游原生函数调用。

## 支持范围

| 接口 | 声明 | 返回 | 结果回传 |
| --- | --- | --- | --- |
| `/v1/chat/completions` | `tools:[{type:"function",function:{name,parameters}}]` | `message.tool_calls`，`finish_reason:"tool_calls"` | `role:"tool"`，保留 `tool_call_id` |
| `/v1/responses` | `tools:[{type:"function",name,parameters}]` | `function_call`，JSON 字符串 `arguments` | `function_call_output`，保留 `call_id` |
| `/v1/responses` | `tools:[{type:"custom",name,format:{type:"text"}}]` | `custom_tool_call`，字符串 `input` | `custom_tool_call_output`，保留 `call_id` |
| `/v1/messages` | `tools:[{name,input_schema}]` | `tool_use`，`stop_reason:"tool_use"` | 用户消息中的 `tool_result`，保留 `tool_use_id` |

函数参数必须是符合声明 JSON Schema 的对象；网关检查名称、参数和调用数量，拒绝外部 Schema 引用，不加载服务器文件或远程 Schema。工具名须唯一，为 1–128 个字母、数字或 `_`、`-`、`.`、`:`。最多 128 个工具，完整工具目录不超过 48 KiB 或提示词限额的一半，以较小值为准；原始声明 JSON 另有 256 KiB 上限。

不支持的声明会返回 400，包括托管搜索/计算机工具、MCP 服务端工具声明、版本化 Anthropic 工具、Chat 自定义文本工具、语法约束自定义工具，以及旧版 `functions` / `function_call`。调用方可以把 MCP 工具展开成普通函数。Responses 嵌套 Chat 函数形状也可兼容。

Codex `additional_tools` 和其专用执行工具保留原有 JS 工具桥。旧版无 Schema 的平铺 `exec_command` 仍按 Codex 处理；普通带 Schema 的函数、`exec_query` 等名字走通用桥。不要把通用自定义文本工具命名为 Codex 专用的 `exec`、`exec_command`、`shell`、`write_stdin` 或 `apply_patch`。

## 工具选择

| OpenAI 参数 | Anthropic 参数 | 行为 |
| --- | --- | --- |
| `"auto"` 或省略 | `{type:"auto"}` 或省略 | 可调用工具，也可直接回答。HTTP 200 且没有调用不代表故障 |
| `"none"` | `{type:"none"}` | 禁止工具调用 |
| `"required"` | `{type:"any"}` | 必须返回至少一个合法调用，否则失败 |
| Chat `{type:"function",function:{name:"lookup"}}`；Responses `{type:"function",name:"lookup"}` 或 `{type:"custom",name:"patch"}` | `{type:"tool",name:"lookup"}` | 只允许一个指定工具调用 |

OpenAI `parallel_tool_calls:false`、Anthropic `disable_parallel_tool_use:true` 限制最多一个调用。违反限制会失败，网关不会擅自保留第一个。`allowed_tools` 等其他选择格式返回 400。

## Responses 完整往返示例

从 `GET /v1/models` 获取可用模型名，替换下方的 `YOUR_MODEL`。`base_url` 指向网关的 `/v1`，Key 使用网关 API Key。

```python
import json
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8787/v1", api_key="YOUR_GATEWAY_KEY")
tools = [{
    "type": "function",
    "name": "lookup",
    "description": "查询城市天气",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"],
        "additionalProperties": False,
    },
}]

first = client.responses.create(
    model="YOUR_MODEL", input="请查询巴黎天气", tools=tools,
    tool_choice={"type": "function", "name": "lookup"},
    parallel_tool_calls=False,
)
calls = [item for item in first.output if item.type == "function_call"]
assert len(calls) == 1
args = json.loads(calls[0].arguments)
assert calls[0].name == "lookup" and isinstance(args["city"], str)

# 此处由你的应用执行 lookup，而不是让网关执行。
result = {"city": args["city"], "temperature_c": 18}  # 示例工具结果
second = client.responses.create(
    model="YOUR_MODEL", previous_response_id=first.id, tools=tools,
    tool_choice="auto",
    input=[{"type": "function_call_output", "call_id": calls[0].call_id,
            "output": json.dumps(result, ensure_ascii=False)}],
)
print(second.output_text)
```

结果要按每个调用的 ID 回传。并行调用须一次回传全部结果，未知、重复或缺失的结果返回 400。工具失败也要回传错误结果；Anthropic 可设置 `is_error:true`。结果可为文本或受支持的文本/图片内容数组；当前图片使用现有上传与 URL 访问保护，历史中的图片保留附件标记。

`previous_response_id` 的转录快照按调用方隔离，只存在内存中。每条回复创建后有效 30 分钟，全局最多 256 条、总预算 16 MiB；每个调用方另限 64 条、4 MiB，超过自身限额时先淘汰自己的最旧记录。单条快照超过 4 MiB 不缓存。分支从指定回复的快照恢复，不读取最新分支。普通 Responses 回复有完整历史时也会记录，便于中途加入工具；普通请求不会因此进入工具模式。`store:false` 禁止快照存储。句柄未知、过期或被淘汰时，工具续接返回 `previous_response_not_found`；重发完整消息、调用和结果历史，并省略旧句柄即可恢复。顶层 `instructions` 只作用于当前请求，不从旧句柄继承。

完整工具参数和当前结果不截断。历史超过上游单条提示词预算时，只按完整往返组省略最旧历史并标记，原生会话恢复可分段补种；当前请求仍超限则返回 `context_length_exceeded`。应用应根据此错误压缩历史或缩小工具返回内容。

## 流式与错误

三种接口均支持同步和 SSE。通用工具模式先校验完整模型输出，再发送正文和工具调用；等待期间每 15 秒发送心跳，不输出未经校验的 JSON、围栏或上游预览。Responses 发出工具项 `added → arguments/input delta → done → output_item.done → response.completed`，有一致的 ID、索引和序号；Anthropic 使用 `input_json_delta`。这不代表上游最终答案逐 token 返回。

| 错误 | 处理 |
| --- | --- |
| `400 invalid_tool_request` | 检查工具声明、选择和结果 ID；返回消息说明原因 |
| `400 tools_too_large` | 精简工具清单或 Schema |
| `400 previous_response_not_found` | 带完整历史重发，移除旧句柄 |
| `400 context_length_exceeded` | 压缩历史或缩小当前输入 |
| `502 tool_bridge_invalid_output` | 模型没有遵守强制调用、声明、Schema 或格式；网关不伪造调用、不自动进行格式修复推理 |

流已开始时 HTTP 状态仍是 200，失败通过 Chat 错误帧、Responses `response.failed` 或 Anthropic `error` 事件返回，不会发送成功终态。客户端必须检查事件终态。部分 SDK 默认重试 5xx，是否重试由应用自己的策略决定。

接入 CastWorld 时，先用指定工具选择跑通上面的“调用—执行—结果回传—继续回答”，再用实际任务验证。源码和模拟上游测试通过不等于实际 CastWorld 工作流已经验证。
